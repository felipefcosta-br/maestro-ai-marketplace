# Briefing template

Fill in only what is needed. Be specific and short. Never include secrets, credentials or customer data.

```
GOAL
<one sentence: what must be done at the end>

MINIMAL CONTEXT
<what is already known, decisions made, what was already tried and failed>

FILES / AREAS
<paths, modules or commands that matter; docs to read, e.g. docs/architecture.md>

CONSTRAINTS
<what not to touch, conventions to follow, scope limits, no network/installs>

DEFINITION OF DONE
<how to know it is finished: tests that must pass, expected behavior>

OUTPUT MODE
<summary | didactic>
```

## Tips
- Write as if the agent knew nothing about the conversation, because it does not.
- Point to files and lines instead of pasting large excerpts.
- Give the project's test command (see AGENTS.md) when the agent needs to run it.
- For read-only agents (researcher, analyst, architect, reviewer), say explicitly that nothing may be changed.
