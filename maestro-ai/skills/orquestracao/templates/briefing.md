# Template de briefing

Preencha só o necessário. Seja específico e curto. Nunca inclua segredos, credenciais ou dados de clientes.

```
OBJETIVO
<uma frase: o que deve estar pronto ao final>

CONTEXTO MÍNIMO
<o que já foi descoberto, decisões tomadas, o que já foi tentado e falhou>

ARQUIVOS / ÁREAS
<caminhos, módulos ou comandos relevantes; docs a ler, por exemplo docs/architecture.md>

RESTRIÇÕES
<o que não tocar, convenções a seguir, limites de escopo, sem rede/instalação>

CRITÉRIO DE PRONTO
<como saber que terminou: testes que devem passar, comportamento esperado>

MODO DE SAÍDA
<resumo | didático>
```

## Dicas
- Escreva como se o agente não soubesse nada sobre a conversa, porque ele não sabe.
- Aponte arquivos e linhas em vez de colar trechos grandes.
- Informe o comando de teste do projeto (veja o AGENTS.md) quando o agente precisar rodá-lo.
- Se a tarefa for de um agente de leitura (pesquisador, analista, arquiteto, revisor), diga explicitamente que não deve alterar nada.
